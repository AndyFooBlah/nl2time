- 2026-11-15T08:23Z [decision] #32 design: a dedicated `until {end, exclusive?}` op rather than `between(unbounded, X)`. Whether "by X" is a deadline or a history bound depends on `now`, so the IR must say "up to X" and leave the choice to the engine (stored IR still re-resolves correctly). Deadline readings win whenever any reading of X is ahead, so every previously non-empty result is unchanged; open start only replaces what used to be zero candidates. Values carry `start: null`; internally a year-100 sentinel, so no ZInterval change.

- 2026-11-15T22:46Z [decision] (Claude, by symmetry with the owner's #32 decision D1 "unbounded start") New IR op `after {start, inclusive?}`, the mirror of `until`: a start that is over runs to now (like "since"); otherwise the end is unbounded and `TimeValue.end` is null. Plain "after X" starts where X ends ("after March" = April on); the inclusive forms start where X starts; clock times start at the time itself ("after 5pm" = 17:00, not 18:00). This matches Duckling's open intervals.
